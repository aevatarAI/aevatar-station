# 服务交接文档

## 概述

本文档为Aevatar Station项目中三个核心服务的技术交接文档，旨在帮助开发团队成员快速理解服务架构、功能特性和使用方法。

### 涵盖的服务
1. **WorkflowOrchestrationService** - 工作流编排服务
2. **WorkflowRunService** - 工作流运行服务  
3. **TextCompletionService** - 文本补全服务

## 1. WorkflowOrchestrationService 工作流编排服务

### 1.1 服务概述

**文件位置**: `station/src/Aevatar.Application/Service/WorkflowOrchestrationService.cs`

**主要职责**: 
- 统一的工作流编排服务实现，使用新的Agent描述获取方案
- 根据用户目标生成工作流视图配置，直接返回前端可渲染的格式
- 管理业务Agent类型过滤和组织
- 提供智能布局算法优化工作流节点展示

### 1.2 核心接口

#### 主要接口
```csharp
public interface IWorkflowOrchestrationService
{
    Task<AiWorkflowViewConfigDto?> GenerateWorkflowAsync(string userGoal);
}
```

#### 核心方法详解

**GenerateWorkflowAsync(string userGoal)**
- **功能**: 根据用户目标生成工作流视图配置
- **参数**: `userGoal` - 用户目标描述（最少10个字符）
- **返回值**: `AiWorkflowViewConfigDto?` - 前端可渲染的工作流视图配置
- **异常**: 当用户目标过短时抛出`UserFriendlyException`

### 1.3 依赖服务注入


### 1.4 核心业务流程

#### 工作流生成流程
1. **输入验证**: 检查用户目标长度（最少10字符）
2. **Agent过滤**: 调用`GetBusinessAgentTypes()`获取业务Agent，排除系统Agent
3. **描述获取**: 通过反射+DescriptionAttribute获取Agent描述信息
4. **AI调用**: 调用`WorkflowComposerGAgent`处理AI相关逻辑
5. **JSON解析**: 将AI生成的JSON解析为前端格式
6. **布局应用**: 应用智能布局算法计算节点坐标

#### Agent过滤逻辑
```csharp
private List<Type> GetBusinessAgentTypes()
{
    var systemAgents = _agentOptions.CurrentValue.SystemAgentList;
    var availableGAgents = _gAgentManager.GetAvailableGAgentTypes();
    
    // 排除OrleansCodeGen和系统Agent
    var businessAgentTypes = availableGAgents
        .Where(a => !a.Namespace?.StartsWith("OrleansCodeGen") == true)
        .Where(a => !systemAgents.Contains(a.Name))
        .ToList();
        
    return businessAgentTypes;
}
```

### 1.5 布局算法

#### 智能层次布局
- **算法**: 基于节点连接关系的拓扑排序分层
- **特性**: 高精度坐标计算，支持14位小数精度
- **优化**: 使用黄金比例和正弦波形式的微调，避免节点重叠
- **备用方案**: 当智能布局失败时，回退到高精度网格布局

#### 坐标生成策略
```csharp
// 高精度坐标格式
node.ExtendedData.XPosition = x.ToString("F14"); // 14位小数精度
node.ExtendedData.YPosition = y.ToString("F14");
```

### 1.6 配置依赖

#### AIServicePromptOptions 配置项
- `SystemRoleTemplate` - 系统角色定义模板
- `AgentCatalogSectionTemplate` - Agent目录章节模板
- `OutputRequirementsTemplate` - 输出要求模板
- `CriticalConstraintsTemplate` - 关键约束模板
- `JsonFormatSpecificationTemplate` - JSON格式规范模板

#### AgentOptions 配置项
- `SystemAgentList` - 系统Agent列表，用于过滤业务Agent

### 1.7 错误处理策略

- **输入验证**: 用户目标长度检查，抛出友好异常
- **JSON解析**: 包装JsonException，记录详细错误日志
- **Agent处理**: 单个Agent处理失败不影响整体流程
- **布局失败**: 自动回退到网格布局备用方案

### 1.8 性能考虑

- **日志作用域**: 使用`using var scope`管理日志上下文
- **异步处理**: 所有IO操作使用异步方法
- **内存优化**: 及时释放大对象，避免内存泄漏
- **并发安全**: 每次请求创建新的Agent实例避免并发冲突

### 1.9 使用示例

```csharp
// 基本调用
var result = await _orchestrationService.GenerateWorkflowAsync("创建一个数据处理和可视化的工作流");

// 检查结果
if (result != null && result.Properties.WorkflowNodeList.Count > 0)
{
    // 处理成功生成的工作流
    Console.WriteLine($"生成工作流: {result.Name}，包含 {result.Properties.WorkflowNodeList.Count} 个节点");

```

### 1.10 注意事项

⚠️ **重要提醒**:
- 用户目标描述需要具体明确，过于简单会导致生成失败
- 系统Agent列表配置影响可用的业务Agent范围
- 布局算法基于时间戳随机数，确保每次生成的坐标都有微调
- WorkflowComposerGAgent的初始化和调用需要严格按照顺序执行

#### 配置验证流程
```csharp
private async Task ValidateWorkflowConfigurationAsync(Guid viewAgentId)
{
    // 1. 获取Agent配置
    var agentDto = await _agentService.GetAgentAsync(viewAgentId);
    
    // 2. 反序列化配置
    var configJson = JsonConvert.SerializeObject(agentDto.Properties);
    var viewConfigDto = JsonConvert.DeserializeObject<WorkflowViewConfigDto>(configJson);
    
    // 3. 并行验证所有节点
    var validationTasks = viewConfigDto.WorkflowNodeList.Select(ValidateWorkflowNodePropertiesAsync);
    await Task.WhenAll(validationTasks);
}
```

#### 节点属性验证
- **AgentType检查**: 确保节点有有效的Agent类型
- **JsonProperties验证**: 检查JSON格式和反序列化
- **Schema验证**: 使用SchemaProvider验证配置符合Agent要求
- **自定义验证**: 支持IValidatableObject接口的自定义验证逻辑

### 2.5 执行机制

#### 重试策略
```csharp
private async Task<bool> ExecuteWorkflowAsync(Guid coordinatorAgentId, WorkflowRunRequestDto request)
{
    const int maxRetries = 20;           // 最大重试次数
    const int retryDelayMs = 1000;       // 重试间隔1秒
    
    for (var attempt = 1; attempt <= maxRetries; attempt++)
    {
        // 检查事件可用性
        var targetEvent = agentState.EventInfoList.Find(i => 
            i.EventType.FullName == "Aevatar.GAgents.GroupChat.WorkflowCoordinator.GEvent.StartWorkflowCoordinatorEvent");
            
        if (targetEvent != null)
        {
            // 发布工作流启动事件
            await _subscriptionAppService.PublishEventAsync(new PublishEventDto
            {
                AgentId = coordinatorAgentId,
                EventType = targetEventType,
                EventProperties = request.EventProperties
            });
            return true;
        }
        
        // 延迟后重试
        await Task.Delay(retryDelayMs);
    }
    return false;
}
```

### 3.1 服务概述

**主要职责**:

- **参数**: `request` - 包含UserGoal的补全请求
- **返回值**: `TextCompletionResponseDto` - 包含补全选项列表的响应

### 3.3 依赖服务注入

### 3.4 核心业务流程

#### 补全生成流程
1. **输入验证**: 检查用户输入长度（15-250字符）
2. **Agent创建**: 为每次请求创建新的TextCompletionGAgent实例
3. **提示词构建**: 构建包含角色、任务、规则、示例的完整系统指令
4. **AI初始化**: 使用系统指令和LLM配置初始化Agent
5. **补全生成**: 调用Agent生成多个补全选项
6. **响应构建**: 包装结果为标准响应格式

#### 提示词构建策略
```csharp
private string BuildTextCompletionSystemInstructions(string userInput)
{
    var promptBuilder = new StringBuilder();
    
    // 1. 系统角色定义
    promptBuilder.AppendLine(_promptOptions.CurrentValue.TextCompletionSystemRole);
    
    // 2. 任务指令（包含用户输入）
    var taskInstructions = _promptOptions.CurrentValue.TextCompletionTaskTemplate
        .Replace("{USER_INPUT}", userInput);
    promptBuilder.AppendLine(taskInstructions);
    
    // 3. 重要规则
    promptBuilder.AppendLine(_promptOptions.CurrentValue.TextCompletionImportantRules);
    
    // 4. 示例
    promptBuilder.AppendLine(_promptOptions.CurrentValue.TextCompletionExamples);
    
    // 5. 输出格式要求
    promptBuilder.AppendLine(_promptOptions.CurrentValue.TextCompletionOutputRequirements);
    
    return promptBuilder.ToString();
}
```

### 3.5 输入验证机制

#### 严格的长度控制
```csharp
private void ValidateUserGoal(string userGoal)
{
    if (string.IsNullOrWhiteSpace(userGoal))
        throw new UserFriendlyException("User goal cannot be empty.");
        
    if (userGoal.Length < 15)
        throw new UserFriendlyException("User goal must be at least 15 characters long.");
        
    if (userGoal.Length > 250)
        throw new UserFriendlyException("User goal cannot exceed 250 characters.");
}
```

#### 验证设计原理
- **最小长度(15字符)**: 确保有足够的上下文信息生成有意义的补全
- **最大长度(250字符)**: 控制提示词长度，优化AI模型响应速度和质量
- **空值检查**: 防止无效输入导致的处理异常

### 3.6 Agent生命周期管理

#### 实例隔离策略
```csharp
public async Task<TextCompletionResponseDto> GenerateCompletionsAsync(TextCompletionRequestDto request)
```

- **资源隔离**: 单次请求失败不影响其他请求
- **内存优化**: Agent实例在请求结束后自动回收

## 4. 服务间交互关系

### 4.1 协作模式

#### 工作流完整生命周期
1. **WorkflowOrchestrationService** - 负责工作流设计和生成
2. **WorkflowRunService** - 负责工作流执行和监控
3. **TextCompletionService** - 可为工作流描述提供智能补全

#### 数据流转
```
用户输入 → TextCompletionService → 补全建议
用户确认 → WorkflowOrchestrationService → 工作流配置
工作流配置 → WorkflowRunService → 执行结果
```

### 4.2 共同设计模式

#### 一致的架构原则
- **依赖注入**: 所有服务都通过构造函数注入依赖
- **异步优先**: 核心方法都采用async/await模式
- **错误隔离**: UserFriendlyException vs 系统异常的分层处理
- **日志规范**: 统一的日志格式和作用域管理

#### 配置管理
- **共享配置**: AIServicePromptOptions提供统一的提示词管理
- **服务专用**: 各服务有自己特定的配置项和验证规则
- **环境感知**: 支持不同环境的配置切换和热更新

### 4.3 扩展性设计

#### 水平扩展支持
- **无状态设计**: 所有服务都是无状态的，支持多实例部署
- **Orleans集成**: 通过Orleans Grain实现分布式状态管理
- **配置外化**: 关键配置通过IOptionsMonitor支持运行时更新

#### 功能扩展点
- **Agent扩展**: 支持新的AI Agent类型接入
- **布局算法**: WorkflowOrchestrationService支持新的布局策略
- **验证规则**: WorkflowRunService支持自定义验证逻辑扩展
- **补全策略**: TextCompletionService支持不同的补全算法

- **超时**: 合理配置各种超时参数，避免请求堆积

### 5.2 监控要点

#### 关键指标
- **请求量**: 各服务的QPS和响应时间分布
- **成功率**: 服务调用成功率和错误类型分布
- **资源使用**: CPU、内存、网络IO的使用情况
- **依赖健康**: Orleans Silo和外部服务的健康状态

#### 告警策略
- **响应时间**: 超过预期阈值的请求比例
- **错误率**: 连续错误或错误率突增的情况
- **资源耗尽**: 内存不足或CPU过载的预警
- **依赖异常**: 关键依赖服务不可用的告警

## 6. 故障排查手册

### 6.1 常见问题

#### WorkflowOrchestrationService常见问题
1. **空工作流生成**: 检查SystemAgentList配置，确保有可用的业务Agent
2. **布局异常**: 查看日志中的布局计算错误，通常会自动回退到网格布局
3. **AI调用失败**: 检查WorkflowComposerGAgent的初始化和网络连接

#### WorkflowRunService常见问题
1. **配置验证失败**: 检查节点的AgentType和JsonProperties格式
2. **执行超时**: 增加重试次数或检查WorkflowCoordinatorGAgent状态
3. **事件发布失败**: 确认EventProperties格式和目标Agent的事件定义

#### TextCompletionService常见问题
1. **输入长度错误**: 前端需要配合进行15-250字符的长度验证
2. **补全质量差**: 检查和优化AIServicePromptOptions中的提示词模板
3. **Agent创建失败**: 检查GAgentFactory配置和Orleans集群状态

### 6.2 调试技巧

#### 日志分析
- **使用日志作用域**: 通过UserId、AgentId等关键标识过滤日志
- **关注错误堆栈**: 系统异常的完整堆栈信息通常包含根本原因
- **检查配置**: 确认IOptionsMonitor中的配置是否正确加载

#### 性能调试
- **监控异步操作**: 检查是否有死锁或长时间等待的异步调用
- **内存泄漏**: 关注大对象的生命周期，特别是Agent实例的释放
- **网络延迟**: 检查Orleans集群和外部服务的网络连接质量
